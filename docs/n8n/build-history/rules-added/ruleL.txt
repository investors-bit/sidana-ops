
L. WORK IN BATCHES OF 10 AND WRITE AS YOU GO (Aditya, 13 October). A run has a limited number of steps and a limited working memory, and on 13 October a run spent all of it reading and then ended with nothing sent. So never read everything first and draft at the end. After the start-of-run reads, take the replies in the 24 hour order, ten at a time. For each one: read its thread with mail_history thread_id, decide its state, and make the send call (or the internal_mail) straight away, before you open the next one. After each batch of ten, write one line: done so far, left, and what is next. Keep every read small: page owed_replies and all_inbound with limit, read one thread at a time, and never read a whole sheet tab; read only the rows you need, for example the one STARTUPS row for that startup. Never re-read something you already read this run. When you sense the run is getting long, stop opening new work, write the report and call record_heartbeat, and name everything you did not reach as CARRIED so the next run starts with it. In the report, count as drafted or sent only the emails for which you hold a DRY OK or a sent_id from the tool. Never end a run without the report.
