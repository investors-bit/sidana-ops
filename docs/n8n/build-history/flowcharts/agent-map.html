How the two deal agents work in n8n

Agent 1 (the four Fundraising Outreach workflows) sends the deals. Every reply that comes back is handled by one of two n8n Agents: the Hot deals agent for the 11 hot startups, and the Deal flow agent for everything else. Both think with Claude Haiku 5.5 on your Anthropic key and act only through n8n tool workflows.

1 · The whole system

Where mail comes from and where it goes

  A1["Agent 1 · Fundraising Outreach A/B/C/D (n8n, 08:00 daily, 4 mailboxes)"] --> INV(("Investors"))
  INV -- reply --> MB["6 Gmail mailboxes: investors@ · dealflow@ · shradhaa@ · akansha@ · admin@ · ceooffice@"]
  FND(("Founders")) <--> MB
  MB -- "copy at :00, 08:00 to 19:00" --> MH["MAIL-HISTORY workflow"] --> DB[("Supabase: mail_log · meetings · task_heartbeat")]
  SHEET[("Google Sheet: PIPELINE · STARTUPS · INVESTOR_CRITERIA · Founders Info")]
  DB --> SPLIT{"Is the startup one of the Hot 11?"}
  SPLIT -- yes --> HOT["Hot deals agent: Mon–Fri hourly 09:40 to 18:40 IST, Sat+Sun 11:40"]
  SPLIT -- no, or not matched --> DF["Deal flow agent: Mon–Fri hourly 09:10 to 18:10 IST, Sat+Sun 11:10"]
  HOT --> TOOLS["n8n tool workflows: read · send · book · write"]
  DF --> TOOLS
  TOOLS --> MB
  TOOLS --> SHEET
  TOOLS --> CAL["Google Calendar + Meet"]
  TOOLS --> FF["Fireflies transcripts"]

One PIPELINE row has exactly one writer: the hot flag decides which agent owns it. Messages that do not match any startup go to the Deal flow agent so nothing is left without an owner.

2 · Every run, both agents

The seven-step run

flowchart LR
  S1["1 · Gap check: read last run time, fire anything missed"] --> S2["2 · Coverage reads: owed replies · all inbound since last run · meetings"]
  S2 --> S3["3 · Hygiene + ledger: close passed rows still chased; list open asks to founders"]
  S3 --> S4["4 · Every reply gets: one of five states"]
  S4 --> S5["5 · Move each deal: one stage forward (reminders, briefs first)"]
  S5 --> S6["6 · Thesis loop (deal flow): or cold outbound + chases (hot)"]
  S6 --> S7["7 · Report, then: record_heartbeat"]

No reply goes unattended

By the end of a run, every message in the agent's scope sits in exactly one of these states, and the report names each one. There is no cap on replies per run.

ANSWEREDsent this run, with its sent_id
ALREADY ANSWEREDour reply is already on the thread
NO REPLY NEEDEDauto-reply, newsletter, calendar note, closing thank-you
WAITINGon a founder or a team member, with what was asked
CARRIEDran out of room; named, and first in the next run
3 · The deal lifecycle, both agents

From interest to a decision

flowchart TB
  SH["Deal shared by email"] -- "investor passes before any meeting" --> CPA["CLOSED_PASS (kind A): thank them; count passes per firm"]
  CPA -- "3rd pass from the same firm" --> THS["Thesis meeting: ask for a 30-minute call to learn their thesis; record it in INVESTOR_CRITERIA"]
  SH -- "investor shows interest" --> IN
  IN["INTEREST: investor asks for a call or a meeting is on the calendar"] --> FA["FOUNDER_ASKED: email founder next run, quote investor's slots"]
  FA -- "founder replies with a time" --> TP
  FA -- "2 h silent" --> NUD["one nudge on same thread"]
  NUD -- "1 h more silent" --> TC["TEAM_CONFIRMING: TIME NEEDED mail to investors@ · dealflow@ · shradhaa@"]
  TC -- "teammate replies with time after calling founder" --> TP["TIME_PROPOSED: match founder time to investor slots; go back and forth until both agree"]
  TP --> TA["TIMES_AGREED"] --> BK["BOOKED: check 4 calendars, create invite (Shradhaa + Chaman always; Aditya only if hot)"]
  BK --> BR["BRIEFED: brief to founder same run, with investor's website"]
  BR --> RM["REMINDED: separate mails to founder and investor about 1 hour before"]
  RM --> AP["AWAITING_PROOF: ask founder how it went; look for Fireflies transcript"]
  AP -- "transcript found" --> HD["HELD → trail mail to everyone"]
  AP -- "no transcript" --> TAPP["TRAIL APPROVAL mail: send only after a yes"] --> HD
  HD --> TR["TRAILED: score the call HIGH / MEDIUM / LOW"]
  TR --> W["WATCHING: chase only the side that owes the next step"]
  W -- "investor passes after the meeting" --> CPB["CLOSED_PASS (kind B): thank them for their time; record the reason in meeting_outcome"]
  CPB --> WR["Saturday weekly founder report: lists the investor and their feedback"]
  W --> CM["COMMITTED: amount, term sheet or written commitment"]

Who owes the next step (WATCHING)

  • They named a date: nothing until it passes, then one note.
  • Founder and investor talking directly: stay out.
  • We owe the answer: answer this run.
  • Investor reviewing something we sent: wait a full week.
  • Founder owes the investor: point him out in the trail mail at day 3, chase him at day 7.
  • Investor quiet: chase weekly; report after 2 to 3 chases.

When Aditya hears about it

  • Only two kinds of email reach him: TIME NEEDED and TRAIL APPROVAL.
  • Escalations go at the top of the run report, never by email.
  • Valuation, terms and structure are routed to him, never negotiated.
4 · What is different between the two

Deal flow agent and Hot deals agent

Deal flow agent · every non-hot deal

  • Owns every startup that is not hot, plus any message that matches no startup.
  • No cold outbound. Only replies on live threads; first deal shares stay with Agent 1.
  • Thesis loop: a firm passing on 3 shared deals before any meeting (hot deals included) gets a request for a 30-minute thesis meeting; a pass with no reason, a blank stage band or a complaint triggers a request for their real criteria, written into INVESTOR_CRITERIA.
  • Standing hold: GroCliq × OG Capital, send nothing.
  • MIS asked from a founder only when an investor asks for it.

Hot deals agent · the Hot 11

  • Spintly, Bon Cuisine, EosNox, HYRGPT, Talent Recruit, Hoora, CLIKD, MindWox, MentorCloud, Road Athena, LearningPad.
  • Sends its own cold outbound (your 8 Oct change), modelled on past emails across all mailboxes that got replies, avoiding ones that drew silence or complaints.
  • Chase ladder: day 3, day 7, then stop and report.
  • Applies founder corrections to STARTUPS and STARTUP_PROFILE.
  • Asks founders for a fresh MIS at most once a month.
  • Deal rules: MentorCloud founder-facing steps skipped; Orbo and Nexcore paused; CLIKD never to Vinners or Udyat.

5 · How it acts

The tools each agent calls

The agents never touch Gmail, Sheets or the database directly. Each action goes through one n8n workflow with its own guard.
